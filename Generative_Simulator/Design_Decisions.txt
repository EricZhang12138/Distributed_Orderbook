
INPUT: 

All possible types of messages from LOBSTER: 
  ┌──────┬────────────────────────────────────┬─────────────────────────────────────────────────────────┐                                                  
  │ Type │           What it means            │              What it represents physically              │                                                
  ├──────┼────────────────────────────────────┼─────────────────────────────────────────────────────────┤                                                  
  │ 1    │ New limit order submission         │ A new order is added to the book                        │                                                
  ├──────┼────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ 2    │ Partial cancellation               │ An existing order's size is reduced                     │                                                  
  ├──────┼────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ 3    │ Full deletion                      │ An existing order is removed entirely                   │                                                  
  ├──────┼────────────────────────────────────┼─────────────────────────────────────────────────────────┤                                                  
  │ 4    │ Execution of a visible limit order │ A resting order was hit by an incoming aggressive order │
  ├──────┼────────────────────────────────────┼─────────────────────────────────────────────────────────┤                                                  
  │ 5    │ Execution of a hidden limit order  │ Same, but for hidden orders (not in the visible book)   │                                                
  ├──────┼────────────────────────────────────┼─────────────────────────────────────────────────────────┤                                                  
  │ 7    │ Trading halt indicator             │ Market state change (halt / quoting / resume)           │
  └──────┴────────────────────────────────────┴─────────────────────────────────────────────────────────┘      
  
We are ignoring type 5 and 7 for now and we only care about orders types 1-4
Type 1-3 are mandatory while type 4 is optional
Type 4 message is basically the fills from the matching engine, informing the model what order has been executed etc.

1. Closed-loop or Open-loop
closed-loop : include type 4 for the generative model 
open-loop : exclude type 4 for the generative model 

For the model to be effective it has to do two things: 
1 - predict the next order 
2 - keep track of the orderbook state

If we include Type 4 message (closed-loop), it implicitly tells the model about the orderbook state (what has been executed etc) whereas 
if we don't include type 4, then the model has to learn about the orderbook states separately. Also, closed-loop is able to deterministicly 
tell the model about the past history regardless of context length, while in open-loop approach, if we exceed the context length, the model 
will never remember the orderbook states

Tokenise PRICE: 
linear bucketing the first 40 tokens and then for 51-60 and 9-0, we use log buckets

Tokenise TIME: 
quantile binning, which basically creates buckets that every data point has equal possibility falling into

Tokenise VOLUME(SIZE): 
log binning with log spaced buckets. The reason why we didn't go with quantile binning is that 62% of order size is 100 and quantile binning will have 
a lot of overlapping edges. Originally we wanted 20 bins but we eventually ended up with 8.
NOTE: for the size field in MODIFY type, it represents the size of order getting reduced  


''' quantile binning: 
a data transformation technique that groups continuous numerical data into categories (bins) 
so that each bin contains an equal number of observations
'''




DECODE: 
For bucketing, quantisation loss will happen in the decoding phase. Below is a common decoding strategy based on different encoding technique

  ┌─────────────────┬──────────────────────────────────────┬──────────────────────────────────────────────────────┬───────────────────────────┬───────────────────────────────────────────────┐     
  │    Strategy     │               Formula                │                       Best for                       │           Cost            │                    Quality                    │     
  ├─────────────────┼──────────────────────────────────────┼──────────────────────────────────────────────────────┼───────────────────────────┼───────────────────────────────────────────────┤     
  │ Arithmetic mean │ (lo + hi) / 2                        │ Equal-width / linear buckets, uniform-ish data       │ Free                      │ Poor for skewed or log data                   │     
  ├─────────────────┼──────────────────────────────────────┼──────────────────────────────────────────────────────┼───────────────────────────┼───────────────────────────────────────────────┤     
  │ Geometric mean  │ int(sqrt(lo * hi))                   │ Log-spaced buckets (np.geomspace), log-distributed   │ Free                      │ Good when bucket is geometrically symmetric   │     
  │                 │                                      │ data                                                 │                           │                                               │
  ├─────────────────┼──────────────────────────────────────┼──────────────────────────────────────────────────────┼───────────────────────────┼───────────────────────────────────────────────┤     
  │ Empirical       │ np.median(values_in_bucket), fit     │ Quantile buckets, any heavy-tailed feature           │ One-time fit + stored     │ Best — minimises mean abs. reconstruction     │     
  │ median          │ once                                 │                                                      │ array                     │ error                                         │
